# Spec 002 vs PR #19

> **DEPRECATED (2026-08-11):** The Sisyphus workflow platform — including the executor, control plane, admin app, and agent credential pool described in this document — has been deprecated in favour of the Claude Code GitHub Action. This was because the GitHub Action is easier to maintain and configure, and more customizable than the bespoke infrastructure it replaced. This document is retained as a historical design record only; the packages and apps it describes have been removed from the repository.

tree. [SPEC-003-004-IMPACT](./SPEC-003-004-IMPACT-2026-08-09.md) assessed how specs 003 and 004 changed that
list while 003 was 53/129 and in flight. **This document re-runs that assessment against 003 as delivered** —
[PR #19](https://github.com/bluetel/bluetel-ai/pull/19), 125 of 129 tasks, 316 files, +52,864 lines.

**Method**: read-only, against the PR head `c32258d` (`origin/feature/agent-credential-pool`) diffed against
its base `origin/feature/sisyphus` (`0771a01`). Every verdict below was checked in the PR's own tree, not
inferred from its description.

**Baseline is valid**: spec 002's `tasks.md` is byte-identical between this analysis branch and PR #19's base,
so the 34-task list is the same list on both sides.

> `session/idle-ceiling.ts` and `jobs/reconcile.ts` … Its shared home is `packages/sisyphus-api`, which neither

and imported by all three consumers —
`apps/sisyphus-executor/src/session/idle-ceiling.ts:51`,
`apps/sisyphus-control-plane/src/jobs/reconcile.ts:1`, and
`apps/sisyphus-admin/src/components/workflows/parking-countdown.ts:2`. Both applications re-export it for

The PR's own comment names the task's reasoning back at it: _"It is now one value … the shared home the comment
that used to be here said the move belonged in."_ This is the only one of the 34 that can be ticked.

### Re-scope, do not tick: T231 ⚠️

The companion document ranked this A1 — the highest-severity open item. PR #19 built **the mechanism it asked
for** and did **not** connect the half that made it urgent.

**Done**: `apps/sisyphus-executor/src/output/secret-registry.ts` implements `createSecretRegistry`, giving
`current: () => readonly KnownSecret[]` — precisely T231's _"make `secrets` a `() => readonly KnownSecret[]`
resolved at each redaction site"_. `run/execute.ts:283` builds the registry and threads
`secretRegistry.current` through the segment writer, the sanitisers and the park report. The design note is
good, including why `current()` must return a stable array reference so the expanded index is not rebuilt per
chunk. The rotating agent credential is registered through it.

**Not done**: `assembleRun` still returns an `options` object with **no `secrets` key** — verified in the PR
head at `apps/sisyphus-executor/src/run/assemble.ts:247-268`, unchanged from the state the companion document
described. So `runExecutor` reads `options.secrets ?? []` and seeds the registry **empty on every real run**.

The consequence T231 was written about therefore survives verbatim: **bundle-installed client credentials
still reach the streamed log protected only by pattern matching in `output/secret-patterns.ts`.** What changed
is that the remaining work is now small and well-defined — seed the registry from the bundle's installed
credentials at phase 5 — rather than architectural.

**Recommendation**: rewrite T231's body to the seeding half, note the registry as delivered by 003/T054, and
keep it open at the same severity. Do not tick it: the ticked half is not the half that was dangerous.

### Rewrite before running: T218, T219

Not completed and not supersedable — but their scripts are now wrong, and because `quickstart.md` was not
reconciled the wrongness is still sitting in the file a person would follow. T218's "the process still alive"
check inverts on the default path. T219 gains a new case from `003/FR-043`: a stopped instance that cannot be
restarted must be recovered from snapshot onto a fresh instance **holding the same credential**, with the
substitution recorded.

### Delete as no longer relevant: none

No task in the 34 has been made unnecessary by PR #19.

## 6. Three things worth a decision

**PR #19 is `CONFLICTING` against its base**, and its base is `feature/sisyphus` while this analysis and spec
004 sit on `feature/sisyphus-4`. Three branches now carry spec-002-relevant state. Worth settling the merge
order before more analysis is written against a moving base.

**PR #19's own four unticked tasks are the same shape as spec 002's fourteen.** T123 (walk quickstart 1–8
against a real stage), T124 and T125 (two questions only a real provider account answers), T127 (SC-007 as two
figures) are all recorded in `specs/003-agent-credential-pool/outstanding.md` with what each needs and what is
assumed in its place. That is the right way to leave them. It also means **the credential pool has never run on
a stage either** — so the "nothing has been run end to end" finding now spans both features, and a single
stage exercise could discharge parts of both.

**The PR's defect list is the best evidence yet for T215–T217.** Four defects, each _"caught by trying to
falsify a test rather than by reading code"_ — including a race suite that passed with the exclusivity index
dropped, and a streaming redactor that emitted a secret in halves across a buffer boundary. That is exactly
the practice T215–T217 asks for, applied to 003's gates. The three spec 002 gates it was written for are still
unverified. The technique is evidently working; point it at the remaining three.
